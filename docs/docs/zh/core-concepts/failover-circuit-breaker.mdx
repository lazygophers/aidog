# 故障转移与熔断

故障转移会在当前候选失败后尝试同组下一个兼容候选，不跨分组，也不强行使用不兼容模型或协议。

失败分类（2026-09-28 起）：**连接建立失败（connect 失败）计入熔断**，临时踢出一段时间后自动半开探测恢复，且带本地网络保护（短时间窗内过半候选平台同时 connect 失败时判为本机网络问题，不计入熔断）；非 connect 的网络错误（读超时/中途掐线）、上游 5xx、200 空响应**不影响调度**——下一轮仍按原优先级选择该平台；上游主动限流（429 非配额类）同样计入熔断；余额不足（402）与鉴权失败（401）触发**固定 5 分钟内存冷却**，不改变平台启用状态，到点自动回调度；配额耗尽（429 配额类）按上游给出的重置时间冷却。熔断 Open 与冷却截止持久化到 platform.db，代理重启后恢复（过期即弃）。同一次请求内某平台 connect 失败后，与其共享 base_url 的兄弟平台条目会被跳过（站级死站不重复撞）。排障时先看日志失败阶段，再检查候选顺序、平台状态、模型与端点协议。高峰禁用是独立闸门。

平台 DB 级自动禁用（auto_disabled，指数退避）的写入路径已于 2026-09-28 移除；历史遗留行仍按原语义过滤与恢复（存量兼容），职责由熔断持久化整体接管。
