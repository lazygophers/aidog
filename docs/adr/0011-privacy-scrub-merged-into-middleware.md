# ADR 0011: 隐私脱敏并入中间件（Reversible Mask），删除独立隐私脱敏

## 背景

出站隐私保护曾有两套各自独立的机制：

1. **中间件规则**（ADR 0003）：条件树 + 动作链，`mask` 是不可还原的固定文本替换，只改 messages + system。
2. **设置页「隐私脱敏」**：独立开关（setting `privacy/scrub`），在出站 JSON 的全部字符串值里检测机密与个人信息，
   换成占位符 `{{PII_<TYPE>_<8hex>}}`，响应返回客户端时还原；可选本地 PII 模型后端。

两套都在识别 API key、邮箱、银行卡、身份证，入口、优先级、生效范围各说各的：用户无法判断一段文本被谁改、
改成了什么、回来时会不会还原；占位符引擎与检测规则各存一份。

## 决策

1. **隐私脱敏全部由中间件负责**，删除 `privacy/scrub` 设置形状、设置缓存字段、入口闸、`privacy_scrub_get/set/preview`
   命令、`PrivacyScrubSection` 设置区块、本地 PII 模型后端与检测服务地址、旧检测器 `detect.rs`、8 locale `privacy.*` 文案。
2. **`mask` 动作加模式**：Fixed Mask（固定文本，不还原，原行为，缺省）与 Reversible Mask（占位符，响应返回时自动还原，
   流式同样还原）。同一条请求侧规则同时完成替换与还原，不新增动作种类。
3. **识别只用「正则 + 校验位」**（luhn / iban / cn_id），不新增匹配方式。旧 6 类在内置规则里都有对应，缺的 PEM 私钥、
   Bearer token 新增为内置规则（默认启用）。
4. **内置脱敏规则全部为 Reversible + 全部内容**。范围「全部内容」遍历出站请求每个字符串叶子，固定跳过表
   （图片 / 音频 / 文档 base64 data、thinking 签名、tool call id、顶层 model 名）写在代码里，不可配置。
5. **占位符引擎唯一实现在中间件层**（`aidog_middleware::placeholder` / `reversible`）：确定性占位符、每请求内存映射表、
   JSON 转义还原、流式 `StreamRestorer`。先前规则产生的占位符对后续规则不可见。
6. **执行点**：Reversible 在最终出站 wire body（协议转换之后）执行；Fixed 保持原执行点。应用失败 → fail-closed 503，
   不转发，`blocked_reason='privacy_scrub_unavailable'` 沿用（一个原因串）。
7. **日志各侧一律占位符形态**：用户请求、上游请求、上游响应、用户响应四侧都不含原文；映射表只在内存，不落盘。
8. **「试一试」**：中间件页按当前启用的全部请求侧规则走生产同一对函数，展示替换后文本、命中规则、还原后文本。
9. **旧设置不迁移**：`privacy/scrub` 的残留行留在库里，无行为影响，不清理。

## 后果

- 用户升级后，原先靠旧隐私脱敏的保护改由启用中的内置规则承担；旧开关状态、类型细粒度开关、模型后端设置丢失。
  PEM 私钥与 Bearer token 内置规则默认启用，补上这两类的覆盖。
- 不再有本地 PII 模型后端：没有模型层的健康检查，fail-closed 只覆盖引擎自身错误。
- 只有一个占位符引擎，旧 `gateway::privacy` 模块整体删除（含 6 类检测器与其测试）。
- 日志库任何列不出现被 Reversible Mask 命中的原文。

## 备选方案

- **新增独立动作种类**（如 `mask_reversible`）：动作链、编辑器、校验都要多一条分支，而「替换 + 是否还原」只差一个模式位。
  只有当两种模式的参数集合发散到无法共用一个表单时才成立。
- **新增 detector 匹配方式**（把旧检测器作为一种 match type）：引入第二套识别入口，与「正则 + 校验位」重复。
  只有当出现正则表达不了的识别需求（如上下文语义）时才成立。
- **两个入口并存**（保留设置页隐私脱敏）：用户继续面对两套优先级与范围；只有当隐私脱敏需要中间件规则模型无法表达的全局语义时才成立。
- **自动迁移旧设置**（把 `privacy/scrub` 翻成中间件规则开关）：旧细粒度开关与内置规则不一一对应，翻译会静默改变启用集合；
  只有当旧设置的使用面大且映射可无损时才值得做。用户已明确接受不迁移。
- **保留本地 PII 模型后端**：需要常驻外部服务与健康检查，且检测路径不属于「正则 + 校验位」；只有当正则无法覆盖的 PII
  类别成为实际需求，并愿意承担外部依赖时才成立。
