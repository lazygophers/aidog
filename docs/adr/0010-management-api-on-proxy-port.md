# ADR 0010: 管理接口挂到代理端口、默认开、本机免鉴权

## 背景

用户要在系统设置新增「API」模块，展示与测试接口，并允许第三方程序调用（原话：「系统设置添加新的模块，用于对于api接口的展示和测试，允许第三方使用api调用接口」）。此前只有无界面内核 `aidog-kernel --ui` 在独立端口 9891 提供 `/rpc/<命令>`、`/events` 与网页界面，桌面版没有任何 HTTP 管理入口；2026-09-03 审查裁决管理面只绑 127.0.0.1。四轮 ask-me 拍板（决策账本 `.scratch/memory/2026-11-04.md`「系统设置新增 API 模块」节）。

## 决策

1. **管理接口挂到代理端口**（默认 9890），桌面版与内核版一致；删除独立端口 9891 与内核 `--port`。路径为 `/api/rpc/<命令>`（POST）、`/api/events`（SSE），内核网页界面为 `/api/ui/`。
2. **只接受本机连接**：代理开了「允许局域网连接」时，这三类路径仍按 `/api/*` 既有做法拒绝非回环来源。
3. **默认开，本机免鉴权**：设置里一个开关统一启停桌面版与内核版的管理接口，默认开；可选凭据（沿用 `auth_token`，默认空 = 不校验）填了才要求 `Authorization: Bearer`。内核 `--ui` 只决定是否提供网页界面，开关关着时带 `--ui` 启动报错。
4. **不加浏览器跨站防护**（不校验 Origin / Host / Content-Type）：用户在知悉风险后明确选择。
5. **密钥信息只写不读**：管理接口返回中的密钥信息一律遮成 `***`，专门导出密钥的命令禁用；写入允许，回传 `***` 视为保持原值。

## 理由

1. 用户要求「不独立开新的端口」，第三方只需记一个端口；桌面版不必多开监听。
2. 路径放进 `/api/` 前缀：透传平台会把任意路径转发上游（ADR 0008），裸 `/rpc`、`/events`、`/ui/` 可能与上游路径冲突；`/api/` 已是应用端点的保留前缀。
3. 本机限制沿用代理上已验证的回环判定，局域网设备够不到管理接口。

## 后果

- 已有调用内核 `http://127.0.0.1:9891/rpc/...` 的脚本与内核网页界面的传输层都要改到新地址；`--port` 参数失效。
- **已知风险**：本机浏览器打开的恶意网页可以向管理接口发请求（跨站简单 POST、DNS rebinding），在免鉴权默认下能改配置、跑脚本；响应因无 CORS 头通常读不到，但 DNS rebinding 可读。复活条件：出现针对本机端口的浏览器攻击报告，或用户要求加固——届时首选 Origin / Host / Content-Type 三项校验（对非浏览器调用方零影响）。
- 代理端口未运行时管理接口不可用。

## 备选方案

- 桌面版沿用 9891 新开监听：违背「不开新端口」，两种外壳同机抢端口，弃。复活条件：管理接口需要与代理不同的生命周期（代理关、管理接口开）。
- 多把带权限的 API 密钥：用户选本机免鉴权，弃。复活条件：出现多个第三方需要分别吊销或区分权限。
- 默认关：用户选默认开，弃。
