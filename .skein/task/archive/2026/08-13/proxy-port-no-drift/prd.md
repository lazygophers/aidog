# 代理端口固定不漂移 + 占用即失败提醒 — PRD (主入口)

> 禁写具体文件路径与代码片段 (会很快过期) —— 例外: prototype 产出的能精确编码决策的片段 (状态机/schema/type shape) 可内联, 且须注明来自 prototype。

## 目标
要解决什么 / 用户价值 / 成功长什么样:
- [ ] **用户设的端口就是最终端口** —— 用户在设置里填 9890，此后无论重启多少次、无论中途发生过什么，设置里存的永远还是 9890。当前行为是：端口被占用时自动往上加 1 找一个能用的，**并把这个新端口回写进设置**，于是用户的配置被应用自己改掉了，且一改再也回不去（下次以新端口为起点继续漂）。
- [ ] **占用即失败并明确告知** —— 端口被占时不再偷偷换一个，而是启动失败 + 明确告诉用户「端口 9890 被占用，代理未启动」。用户宁可知道没起来，也不要在一个自己不知道的端口上悄悄跑着（客户端还配着 9890，请求全打空）。
- [ ] **开机自启动失败也看得见** —— 自启动场景没有前端窗口，当前只写一行日志。要让用户在不主动查日志的前提下知道代理没起来。

## 边界
范围内 / 范围外 (非目标) / 已知约束:
- [ ] 范围内：代理启动的端口绑定策略（占用时的行为）、启动后是否回写端口设置、启动失败的用户可见提醒（系统通知 + 托盘菜单标记 + 主窗口内错误条）、相关文案的 8 语言 i18n。
- [ ] **范围外：不做端口值迁移** —— 用户已拍板：代码只保证「以后不再被改写」，当前已被写坏的值由用户自己在设置页改回。禁加任何「检测到端口在某区间内就重置」的自动迁移逻辑（会误改用户故意设的端口）。
- [ ] **范围外：不改端口设置项本身的存储结构** —— 端口已经是持久化设置的一部分（`ProxySettings.port`），本 task 修的是它**被谁改写**，不是它存不存。禁顺手重构 settings schema。
- [ ] **范围外：不动 bind_lan / autostart / silent_launch** 等同结构体内其他字段的语义。
- [ ] 约束：**手动启动与自启动两条路径都要覆盖** —— 两者调的是同一个 command，但失败后的提醒通道不同（手动有前端窗口，自启动没有）。只修一条 = 没修。
- [ ] 约束：端口设置在**代理已运行时**被修改，其行为不在本 task 范围内改动（沿用现状）。
- [ ] 约束：`0.0.0.0` / `127.0.0.1` 两种绑定模式下行为一致 —— 占用判定不因绑定模式而异。

## User Stories
极其详尽地穷举, 覆盖功能各方面 (含边界情况) —— 穷举本身就是逼出边界情况的机械手段:
1. As a 用户, I want 我在设置里填的端口重启后还是那个值, so that 我的客户端配置（`ANTHROPIC_BASE_URL` 等）不会因为端口漂走而全部失效。
2. As a 用户, I want 端口被占用时代理干脆不启动, so that 我不会在「以为它在 9890 跑着」的状态下把请求全打到一个没人监听的端口上。
3. As a 用户, I want 启动失败时看到明确的「端口被占用」而不是泛泛的「启动失败」, so that 我知道该去关掉那个占端口的程序，而不是瞎猜。
4. As a 用户（开机自启动场景）, I want 代理没起来时收到系统通知, so that 我不必主动打开应用才发现代理是停的。
5. As a 用户（开机自启动场景）, I want 托盘菜单能看出代理没起来, so that 我瞥一眼菜单栏就知道状态。
6. As a 用户（手动点启动）, I want 失败信息留在界面上而不是一闪而过, so that 我有时间读完并处理。
7. As a 用户, I want 我把占端口的程序关掉后能直接重试, so that 我不用重启整个应用。
8. As a 非中文用户, I want 这条错误提示在我的语言下也说得清楚, so that 我知道发生了什么。
9. As a 用户, I want 启动成功时一切照旧, so that 这个修复不会给正常路径添乱。
10. As a 用户, I want 端口被占用之外的其他绑定失败（如权限不足、地址非法）也有区分度地报出来, so that 我不会把「没权限绑」误当成「端口被占」去找不存在的占用进程。

## 验收标准
可执行、可核对的完成断言 (逐条):
- [x] 端口被占用时，代理启动**失败**并返回错误，**不再**尝试 port+1..port+100。
- [x] 启动流程**不再把实际端口回写进设置** —— 用户设的端口值在任何启动路径（成功 / 失败 / 自启动 / 手动）后都保持不变。
- [x] 「端口被占用」与「其他绑定失败」在错误信息上可区分（用户能据此判断是去关占用程序还是别的问题）。
- [x] 手动点启动失败时，主窗口内出现**持久错误条**（非一闪而过的 toast），含被占端口号与重试入口。
- [x] 开机自启动失败时，发出**系统通知**，含被占端口号。
- [x] 开机自启动失败时，**托盘菜单**可看出代理未启动。
- [x] 关掉占端口的程序后，用户可在不重启应用的前提下重试并成功启动。
- [x] 启动成功路径行为无变化（端口正确、分组 settings 文件同步、托盘刷新照旧）。
- [x] 新增文案 8 种语言（zh-Hans / en-US / ar-SA / fr-FR / de-DE / ru-RU / ja-JP / es-ES）齐备，`node scripts/check-i18n.mjs` 通过。
- [x] `yarn build` 通过（含 tsc）；`cd src-tauri && cargo clippy` 零 warning；`cargo test` 通过。

## Testing Decisions
什么算好测试 (只测外部行为不测实现细节) / 测哪些模块 / codebase 内的同类测试先例:
- [ ] **主接缝 = 启动函数的返回值**：先占住一个端口，再调启动，断言「返回 Err 且错误可识别为端口占用」+「设置里的端口值未变」。这两条正是用户诉求的全部，且完全不碰内部实现。`gateway/proxy/` 下已有 `#[test]` 先例（`test_integration.rs` / `test_connect.rs` 有 bind 0 端口起服务的既有写法可复用）。
- [ ] **禁断言具体错误字符串全文**（会随文案改动脆断）—— 断言错误的**可判别性**（如错误类型 / 前缀 / 是否含端口号），不断言整句。
- [ ] 前端提醒（错误条 / 系统通知 / 托盘）**不写自动化测试**：跨 Tauri 边界与系统 API，成本远高于收益。改由 check 阶段人工确认一次。i18n 侧靠既有 `scripts/check-i18n.mjs` 静态扫描兜底。
- [ ] **回归防线**：必须有一条测试专门钉住「启动后设置里的端口没被改写」—— 这是本 bug 的根因，没有这条测试它会再回来。
