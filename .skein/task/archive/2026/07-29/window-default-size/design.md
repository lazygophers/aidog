# 窗口默认尺寸与合成面定数 — 详细设计

## 现状

`src-tauri/tauri.conf.json` 的 `app.windows` 单窗口：

```json
{"title":"AiDog","width":1026,"height":759,"maximized":true,"resizable":true}
```

**`maximized: true` 让 `width`/`height` 形同虚设** —— 应用永远以最大化启动。在 2304×1265 的屏幕上，这直接把合成面推到最大。

### 合成面 ∝ 窗口面积（[03] 已证）

| 窗口 | graphics — dev | graphics — release |
|---|---|---|
| 2304×1265 | 231 MB | 252 MB |
| 1150×750 | — | 122 MB |
| 800×600 | 52 MB | — |

dev 拟合 `graphics(MB) ≈ 7.35e-5 × 面积 + 16.7`（干净实验）；release 两点拟合 `≈ 6.34e-5 × 面积 + 67.3` —— **常数项 67.3MB 单独就吃掉整个 71MB 合成面预算**，且那轮 release 量测不干净（同进程内主进程 116→150MB、GPU 28→64MB，缩窗后反升，两点不在同一稳态）。**系数不可信，必须重量。**

## 用户已拍板的取舍

**改默认非最大化，不限制上限。**

- 删 `maximized: true`，默认回 `1026×759`
- **不加 `maxWidth` / `maxHeight` 硬限** —— 用户仍可自由拉大或最大化
- 达标口径 = **默认尺寸下 ≤200MB**
- 「用户拉大窗口就超预算」是**物理事实**，代码规避不了，spec 正面写明

## 方案（当前方案 = 精简守现状）

### 1. 干净的 release 窗口-内存曲线量测

这是本 task 的主体工作，不是背景。[03] 的量测被自身承认不干净，必须重做：

**硬协议**：
- **每个尺寸独立重启 app**（禁同进程内 `osascript` 改窗口后连采 —— [03] 就栽在这）
- 每次等满稳态：**≥10min**（内存曲线有冷 50MB@25s / 稳 149MB@22min 两端）
- release 构建，`open -a` 启动
- 判据只认 `footprint` 的 `phys_footprint` + graphics region 字节；**禁 `ps rss` / `vmmap`**（漏算 `Owned physical footprint (unmapped) (graphics)`）
- **region 数是噪声指标**（[03] 实测同 CSS 下 157/211/218 乱跳），只记字节

尺寸档：至少 4 档，含 `1026×759`（默认）与 2304×1265（最大化对照）。

### 2. 改配置

`tauri.conf.json` 删 `maximized: true`。一行改动。

### 3. 写进 spec

产出文档段落，正面写明：
- 默认尺寸下的实测全进程总和
- 合成面随窗口面积的实测关系式（release 口径）
- 「拉大窗口会超 200MB」是 WKWebView 合成面的物理成本，非缺陷

### 4. 布局回归

`1026×759` 下逐页检查：无内容截断、无横向滚动、Settings 锚点导航正常。红线 3 判据。

## 为什么不选别的

| 备选 | 否决理由 |
|---|---|
| 加 `maxWidth`/`maxHeight` 硬限 | **用户已明确拍板不加** —— 限制用户自由换预算达标，取舍不划算 |
| 保留 `maximized: true`，改口径到 350MB | [03] 已否决改数字方案，用户选了维持 200MB |
| 用代码在超尺寸时降级视觉 | 多一条状态路径 + 视觉不一致，YAGNI |
| 合成面代码级优化 | [03] 已证是窗口面积的物理函数，代码优化不了 |

## 数据流（量测链路）

```
for 尺寸 in [1026x759, 1400x900, 1800x1100, 2304x1265]:
    干净重启 release app（禁复用进程）
    设窗口尺寸 → 等 ≥10min 稳态
    measure.sh mem → 记 phys_footprint / graphics 字节 / 全进程 TOTAL
→ 出曲线表 + release 口径拟合式
→ 删 maximized: true → 复测默认尺寸确认 ≤200MB
```

**与 `frontend-compositing-purge` 的关系**：本 task `deps=[frontend-compositing-purge]` —— 合成面数字必须在**前端动画/层清理之后**测，否则量的是被污染的基线；且二者共享同一量测环境（CLAUDE.md「共享环境先串行化」）。

## 可能性分支（不进当前方案，仅留痕）

- **记忆用户上次窗口尺寸** — 触发条件：若用户反馈默认尺寸每次都要手动调。代价是多一份状态持久化 + 与「默认尺寸达标」口径的说明冲突。
- **超尺寸时的用户提示** — 触发条件：若「拉大就超预算」成为用户实际困扰。可在设置页显示当前内存占用而非弹提示（无侵入）。
- **`maxWidth`/`maxHeight` 软限** — 触发条件：仅当用户改变主意。当前已拍板不加。
