# 编辑时段窗口维度 radio 修复与文案 — 详细设计

架构 / 数据流 / 关键取舍 / 技术选型 (不含调度图, 调度归 task.json):

## 根因

维度选中态**从数据反推**（`dimensionOf(w)`：有月数据→月，有周数据→周，否则→无）。
切到「周几」时，互斥逻辑把月字段清空、周字段因尚未勾选任何一天而保持 `undefined` ——
此刻数据与「无」**完全同形**，下一次渲染 `dimensionOf` 又推回「无」，radio 立刻弹回。

即：**「周几-但一天都没选」与「每天」在数据层不可区分**，而 UI 需要区分它们（前者要露出选择器）。
这是纯派生态（derived state）在存在「空但已进入」中间态时的经典失效。

## 取舍

| 方案 | 评价 |
|---|---|
| 往数据塞空数组当哨兵（`days_of_week: []` 表示「已进入周模式但没选」） | **否决** —— 污染落盘数据与后端语义，PRD 边界明令禁止 |
| 加一个 UI-only 的选中态，数据层不变 | **采纳** —— 中间态本就只属于 UI，不该外泄到持久层 |
| 改 `dimensionOf` 让它更聪明 | **否决** —— 信息在数据里根本不存在，再聪明也推不出来 |

## 方案

弹窗内维护 per-window 的显式维度选中态（UI-only），渲染时优先取它，缺省再回落到 `dimensionOf(w)`。

- 弹窗打开时随窗口副本一同初始化（用 `dimensionOf` 算初值），保证「关掉再打开选中态与数据一致」。
- 切换维度时同时更新该 UI 态与数据（互斥清空逻辑保持不变）。
- 增删窗口时该态需跟着索引变动 —— **按 window 索引存的结构在删除中间窗口时会错位**，这是本方案唯一的坑，实现时须处理（要么改用稳定 key，要么删除时同步搬移）。
- 保存路径完全不碰这个 UI 态：空选择照旧落 `undefined`，数据语义零变化。

## 文案

两个 key 改值，key 名不动：label「维度」→「生效日」；首选项「无」→「每天」。
8 语言各自按母语日常用词翻，**禁机翻直译**（如德语 label 不该是 `Dimension`）。
代码内 `t()` 的 fallback 字面量同步改，否则 locale 缺失时会露出旧文案。

## 测试接缝 (seam)

check 阶段验证的是`行为对不对`而非`跑没跑起来`, 全靠这里选对接缝。三条规则:
1. 优先复用现有接缝, 不新建
2. 取最高接缝 (越靠外部行为越好)
3. 越少越好, 理想 = 1 个

- **接缝 = 弹窗组件本身**（渲染 → 模拟点击 → 断言界面与 `onSave` 回调入参）。这是最高接缝：
  它同时覆盖「选中态对不对」（看选择器有没有露出）与「数据脏不脏」（看 `onSave` 收到什么），
  且完全不碰内部 state 结构。用 React Testing Library，与既有 6 个组件测试同款，**不新建接缝**。
- i18n 侧不另开接缝，复用既有 `scripts/check-i18n.mjs` 静态扫描。
