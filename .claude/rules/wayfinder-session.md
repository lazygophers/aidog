# wayfinder 调研轮：票面预设、agent 派发、ask-ui 解读

2026-09-27 claude-perm-ux 轮（/wayfinder + 后台 research agent）暴露的三个流程缺口。
适用于一切「ask-ui 定向 → 建票 → 派后台 agent 取证 → 结票」的调研型 session。

（同日 cc-sub-mitm 轮验证：1/2/3 三条执行全部到位——票面预设标「未证实」且被票 01 逐条判定、
7 张票 `Status:` 全写对词表、两题自由文本解读经第 4 轮复核确认。无需改文。）

## 1. 票面预设事实必须标「未证实」

该轮两张 research 票的票面预设全被报告推翻：票 01 写「settings 三层级」（实际五层）、
「modes 四个」（实际六个）；票 02 预设「/hooks 可视化编辑」（实际面板已改只读）。
预设来自主会话记忆，写进 Question 时没带来源，下游若不先结取证票就会把错的前提
当靶子。

规则：

1. **Question 里凡来自记忆、未带出处的外部事实，显式标注「未证实，先核对」**，
   并要求 agent 报告里逐条判定票面预设的真假（推翻也算结票产出，不是失败）。
2. **依赖这些事实的下游票必须 `Blocked by` 取证票**（该轮 03/04 已正确挂边，
   缺的只是第 1 条的显式标注）。

## 2. 派 agent 干票，状态迁移指令要贴进派发 prompt

该轮一个 research agent 结票时把 `Status:` 写成 `done`；tracker 约定值是
`claimed` / `resolved`（`docs/agents/issue-tracker.md` Wayfinding operations 节）。
agent 不会自己去读那份 doc——词表不贴进 prompt 就等于没有。

规则：派发 prompt 里原样贴三行：开工置 `Status: claimed`；结票在文末追加
`## Answer` 段并置 `Status: resolved`；**状态词只有这两个**，禁 `done` / `closed`
等近义词。主会话收报告后仍应 grep 一次 `Status:` 核对，别假设 agent 写对了。
2026-10-30 复发：两张票（推荐配置 01、embedding 02）被写成 `done` 且无 `## Answer`，
收尾才发现。词表放在派发 prompt 里仍不够——每张票合并后当场 grep 该票 `Status:` 与 `## Answer`，
不留到 feature 收尾。

## 3. ask-ui 选项题收到「只写补充说明、未选任何选项」

该轮 5 题里 2 题用户只写自由文本没点选项。此时**语义是主会话解读出来的**，
不是用户拍的板。

规则：

1. 解读结果写进 map 的 Notes / 决策历史，标明「用户未选项、系解读」，
   「我说」字段照实抄用户原话，不誊写解读后的版本。
2. 解读承担了方向性权重时（定对象、定终点这类），下一轮 ask-ui 顺带用一题
   复核「我理解你是 X，对吗」，不为省一题把解读当拍板。
3. 镜像情形（2026-10-18）：**自定义选项（custom）被选中但 supplementaryText 为空**
   ——答案语义只有「用户要自定义」没有值，同样是解读不是拍板。方向性权重时下一轮
   表单把该题重发补值（custom 已点可作默认态），不拿「选了 custom」当结论。
4. 复发与变体（2026-10-30 平台-客户端白名单表单 333ff4b01725）：`w_unknown`、`w_paths` 未选项只写补充，
   `w_reject` 选 503 但补充写「400 或者是别的 4xx」（选项与补充冲突）。冲突时**补充文本优先**（更具体），
   但仍记「系解读」，下一张表单原样复核（本线 3d5fe5b9e825 用户补「417」后才算拍板）。
5. 第三次复发（2026-11-06 模型配置重设计表单）：未选项、补充给出可执行值（「6 个变体」）。
   **补充文本含可执行值时直接按值执行**（记「系解读」+ 账本「我说」抄原话），不等下一轮拍板；
   执行不了的残余歧义（本例「变体」没说变的是布局维度还是视觉维度）并入下一张表单原样复核。
   「系解读」只降记账等级，不降执行等级——空等一轮追问是浪费（本轮按 6 直接出稿，省一轮）。

## 4. 插话方案与正式拍板冲突

cc-sub-mitm 轮：用户两次插话提 path 方案（`/tpproxy/<group>`），第 1 轮 ask-ui
正式拍板却选了互斥的 MITM。当轮处置正确（path 摆成选项 A、否掉后 Out of scope
带复活条件），此处流程化，别靠下轮判断力复现：

1. 插话提出的方案是**候选**，不是拍板。下一轮 ask-ui 把它原样摆成选项，
   不因「与当前倾向矛盾」剔除。
2. 正式拍板否掉它 → map 的 **Out of scope** 记一行：方案 + 否掉原因 + 复活条件
   （「仅当 X 才重开评估」）。
3. 后续兜底链里不静默复活：回落路径显式写「回落 X，不回 Y」
   （该轮：回落端口方案，不回 path 方案）。
4. 账本「我说」照抄插话原话，不誊写成拍板版本。

## 5. 覆盖 session 边界（用户明示或 agent 自行连做）

cc-sub-mitm 轮：charting session 按规矩停在 research，用户说「继续直到全部完成」，
同 session 连做票 04/05/06。wayfinder 的「charting 停在 research」「一 session 一票」
是防上下文腐化的默认，两种情况可覆盖：**用户当轮明示**，或 **agent 自行连做且
下一票无新决策、上下文余量足**（2026-09-28 routing-health-optim 轮：03 拍板后连做
04 纯汇编票）。覆盖时：

1. 账本记决策行，「我说」抄原话（用户明示时）；自行连写照「无，自行判断」+ 判断依据。
2. map 的 **Notes** 补一行覆盖事实——cc-sub-mitm 轮和 2026-09-28 routing-health-optim
   轮各漏一次（都只写进账本 / `.scratch/<spec>/memory.md`，其他会话读 map 看不出
   纪律是被覆盖的，会误判成违规）。两处都记，不是二选一。
3. 同 session 连做后续票时，每票收尾照常走 wayfinder 第 5 步（毕业 fog、
   追加 Decisions so far、刷新 frontier），不因连续作业省略 map 维护。

## 6. 多张 grilling 票合并成一张 ask-ui 表单

2026-09-30 jev-decision-proxy 轮：票 04/05/06 合进一张表单，外加一题复核，一轮问完三张票。
可以合并，但要同时满足两个条件：

1. **票之间互不当输入**：B 票的选项不取决于 A 票的答案。有依赖就用 ask-ui 的分支题，
   或拆成两轮，不要把「假设 A 选了 X」写进 B 的选项里。
2. **每题标明所属票号**（题目标题前缀 `[04]` 之类），结票时按票号把答案写回各自的
   `## Answer`，不要把几张票的答案合写进一张票。

上一轮留下来的复核题（第 3、7 条）顺带塞进同一张表单，不为它单独开一轮。

## 7. 收到新答案先对照已定决策查冲突

同一轮：票 03 用户选「过滤并入 filter_candidates」，这会被单平台分组短路绕过
（`candidates.rs:104`），和第 1 轮定的「分组没有决策平台就报错」冲突。当时是人工看出来的。

规则：每张票收到答案、结票之前，逐条对照 map 的 **Decisions so far** 和当天账本，
检查新答案会不会让已定决策在某条代码路径上失效（短路、兜底、bypass 这类最容易漏）。
有冲突时：

1. **不自己挑一边解决**，下一张表单把冲突原样摆出来（「A 与 B 在 X 路径上冲突，
   选哪个」），附冲突点的 file:line。
2. 账本记「改成 / 原本」两边，「原本」写被冲突的那条决策。

## 8. 选项里引用代码先例之前先核实

同一轮：第 1 轮表单写「embeddings 按路径识别」作为先例，后来 Explore agent 查出
embeddings 能识别但转发会报 400，只好在对话里更正。用户可能已经按这个错的先例做了选择。

规则：

1. ask-ui 的选项或 background 里写「现有 X 就是这么做的」，必须带 file:line，
   而且这一轮真读过那段代码（识别到了 ≠ 能跑通，要看到端到端的结果）。
   查不到就标 `推测:`，或者先派 Explore 查清楚再发表单。
2. 发现已经发出去的先例是错的：当场更正，并且检查依赖这条先例的答案，
   受影响的放进下一张表单复核（按第 3 条处理），不默认用户答案不变。

## 9. 等 ask-ui 提交：一开始就给长超时

2026-09-30 perf-backend 轮：后台跑的 `ask-ui ask` 到 Bash 后台默认 30 分钟上限被杀，
用户还没提交；改写 `sleep` 循环等结果被权限拒（也违反禁 sleep 轮询）；最后靠一个
node `setTimeout` watcher 调 `ask-ui resume` 才接上。

1. 用户要读长 background、慢慢拍板的表单，`ask-ui ask` 用后台 Bash 跑时**当场**
   设 `timeout: 7200000`（后台上限 2 小时），不用默认值。
2. 被超时杀掉不代表表单没了：用 `ask-ui resume` 接回同一张表单，别重发新表单。
3. 禁写 `sleep` 循环等提交。

## 10. 派 research agent 的落盘指令要带回退口径（2026-10-01 commandcode-goat 轮）

票 01 的 research agent 实际拿到的工具集只有 web 读取类（无 Bash/Edit/Write），
「把报告写到 .scratch/<spec>/research/」这条指令它根本执行不了——靠 agent 自行
把全文回传、主会话核对后落盘才接上。事后看是运气不是设计。

- 派 agent 前无法预知其工具集时，落盘指令写成双口径：「若无文件写入工具，报告
  全文直接回传，由主会话核对后落盘」——同模式先例：本文件第 2 条「状态迁移指令
  要贴进派发 prompt」、parallel-implement.md 第 2 条「任务与边界一次性写进派发
  prompt」。
- 回传的全文报告落盘时，文件头注明取证方式（如「agent 无本地文件工具，报告经
  主会话对照官方页面核对后写入」——`.scratch/research/2026-10-01.md` 的方法注记
  即此），别让后人以为它出自一手文件操作。

## 11. 报错语义 spec 要对照现有短路路径（2026-10-28 直接模型转发轮）

需求带「必须报错 / 不得静默回落」语义时，既有短路/bypass 会静默绕过新链路：本轮流控
「单平台组 bypass」在多平台组只剩 1 个 Enabled 平台时同样命中（等效单平台组），
「声明平台全禁用 → 503」被静默打到唯一 Enabled 平台；票面没区分 len==1 与「等效单
平台」，agent 复现测试实锤后才把 guard（`direct_ids 非空 && len > 1`）放到短路之前。

规则：

1. spec 定「报错/阻断」语义时，逐条列出会静默绕过它的既有短路路径（单平台 bypass、
   status bypass、passthrough 豁免这类），写明新 guard 相对短路的位置——票面不写
   位置，agent 按最小改动默认放短路之后。
2. 测试必含「等效退化形态」各一例：多平台组退化到只剩 1 个可用平台的行为，与字面
   单平台组（len==1）分开验证。
3. 「字面 X vs 等效 X」的语义差异在 spec / 表单显式拍板，不留 agent 推断。

## 12. 行为改造的拍板点先从现状审计导出（2026-11-06 路由健康选择策略）

需求原话拆不出真正的拍板点——取舍点要对照现状链路导出，才能问在要害上：

1. 行为改造类需求（排序、优先级、过滤这类「现状已有一条链」的），先审计现状链路
   全貌（主键/次键/兜底/短路各是什么），再逐条对照导出拍板点发问。
2. 为什么：路由健康选择四拍板（coding plan 优先是否压过 level_priority、适用模式、
   「便宜」口径、余额维度口径）全部来自先画现状排序链路；审计发现 coding plan 现状
   是「模式排序后的二值上浮」，不审计就问不出「是否压过 level_priority」这道题，
   拍板项与现状脱节，答了也落不了地。
3. 反例：按需求原话直接拆拍板点——「优先使用 coding plan 的」照字面就是一项，
   漏掉它与既有主键的相对位置这一真正要拍的事；agent 只能自行假设，合并时对不上。
4. 与 §8 的分工：§8 管「选项里引用现状先例要真读过」；本条管「拍板点清单本身
   从现状审计导出」，先审计、后发问，顺序不可换。

## 13. 拍板任务执行不能：事实唯一时不回落表单（2026-11-07 registry 审计轮）

表单拍板「补齐 27 平台 logo_url」，agent 双源验证发现 27 个品牌在 simpleicons
全不存在（官方全量清单 3467 图标正则零命中 + CDN 24 个候选 slug 全 404，主会话
抽测 openai/xai/devin 三条复核）——拍板的前提（「有 slug 可补」）被外部事实

- 执行前提被事实否定、且**没有候选方案**（用母公司 logo 顶替属错误品牌映射，
  agent 已否）时，不回落表单重问：按事实唯一收口，账本记「执行不能」条目
  （「我说」照抄表单拍板原话，「为什么」带双源出处），审计报告单列一行告知。
  判据：事实只有一个答案，不存在拍板空间，重问是浪费一轮。
- 有候选方案（A/B 取舍、改口径重做）才回落表单——那是拍板空间，不是执行不能。

## 14. 调研报告的存在性判断必须 grep 代码（2026-11-07 magpie 调研轮）

对比调研报告称「aidog 缺 Gemini 协议」，实现票开工审计发现 Protocol 枚举、
converter、registry 条目全在——报告取协议清单来自 CLAUDE.md 文档的协议列表，
「文档清单里没有」不等于「代码里没有」。

- 「项目缺 / 没有功能 X」这类存在性判断，真值源是代码与 registry 数据
  （grep 枚举 / converter / `src-tauri/defaults/registry/`），不是任何文档
  （含 CLAUDE.md / GLOSSARY.md）——文档清单滞后于代码是常态。
- 与 §8 分工：§8 管「选项里引用先例要真读过那段代码」；本条管「调研报告对
  功能有无下结论前要 grep 过代码再写」。
- 被误判的功能进入实现段时，实现票开工先审计存在性再动手（票 01/02 零改动
  结票即是正确收口，不是浪费：误判在调研段拦下比在代码里撞上便宜）。
