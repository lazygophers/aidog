# 前端组件重构：就近测试按文件名找，选择器锚稳定 id 不锚 DOM

## 规则

1. **改组件渲染层前，按文件名定位就近测试，不靠 grep pattern**：测试与组件同目录同基名（`WindowsEditModal.tsx` ↔ `WindowsEditModal.test.tsx`），直接 `ls <组件目录>/<组件名>.test.tsx` 核存在。grep 零命中只说明 pattern 不匹配，不说明测试不存在（同模式：registry-data-edit.md「验证输出先看格式再 grep」）。
2. **重构前把就近测试的每个选择器过一遍**：测试锚了什么（稳定 id / data-state / getByText 文案 / class 名 / DOM 层级），重设计后哪些会断——断的选择器与组件改动属同一任务文件集，同一个 commit 改掉，不等门禁红了再补。
3. **测试选择器禁锚 DOM 层级和 class 名**，锚稳定 id + `data-state`（例：`WindowsEditModal.tsx:347-350` 的 `dim-${widx}-${opt.key}` + data-state）；也不用 `getByText(文案)` 断言（另一 agent 改 locale 值会假红，见 WindowsEditModal.test.tsx:2 头注释）。新测试照此写。

## 拖拽交互：Vite-only 测不到落点，列人工验收

托盘设置页依赖 Tauri IPC，Vite-only 不挂载（同 ui-color-bug-verify.md 回退节）。dnd-kit 拖拽只能在 vitest 里 mock `DndContext` 直接喂 `onDragEnd`，落点判定（pointer 命中哪个槽）无覆盖。

- 测试断言 `onDragEnd` 之后的状态（如 `moveSegment` 用 arrayMove 而非 swap，2ffa12be4）。
- 回报与账本遗留单列人工验收：候选拖入槽、槽内手柄排序、拖回移除、键盘手柄（pr-merge-discipline.md §2 同口径）。

## 新增整页 UI 验收：深色 + RTL 截图是硬要求

深色一张、RTL 一张，各能抓到单测结构性抓不到的全站级缺陷（例：preflight 阶段缺 button 重置样式 9a5b96916、RTL 下 flex 特异性压过 `flex-col`）。

- **新增整页 / 大块 UI 的验收标准必含 Playwright 真渲染截图两组：dark mode 一组、RTL（ar-SA）一组**（取证法见 ui-color-bug-verify.md 规则 2，`channel: "chrome"`）。截图落 `.scratch/<feature>/`；派发 prompt 写明不可豁免，只允许「渲染未变」依据豁免（parallel-implement.md §15）。单测 / 门禁全绿不构成豁免：button 重置、RTL flex 特异性这类全站级缺陷单测结构性抓不到。
- **页面依赖 Tauri IPC 时，截图用 ui-color-bug-verify.md「mock 传输层真渲染」手法**（`page.route("**/api/rpc/**")` 按命令名喂假数据；假数据形状逐字段对齐真实 IPC 返回）——「Vite-only 挂载不了」不构成跳过截图的理由。
- 图表 / 画布 / 动效类组件票的截图验收照旧走 parallel-implement.md §14（该节管组件级，本节管整页级，两者都含深色 + RTL）。

## 响应式自适应票：宽屏撑满 + 溢出走卡内滚动 + 空态截图不算覆盖

自适应目标两句话：窄窗不遮挡、宽屏撑满且比例协调（2026-11-26 首页/详情/会话/托盘自适应轮先例）。

1. **「删 maxWidth 封顶」≠ 自适应完成**：去掉 1200px 封顶（2e5e33444）后流量图六列仍要单独修排版（列间距、标签截断、标签互碰，4e920cc2c）。验收截图加宽屏档 2000px（与小图表票四档 900/1024/1100/1440 合成五档，矮窗另加一档如 650 高），宽屏档断言「内容撑满、比例协调、无右侧裁切」，不是「不报错即可」。
2. **溢出优先卡内横向滚动，不把内容赶出卡片**：窄窗修复先例是会话页工具栏换行 + 会话行窄档列模板（f22818b15），不是把列整列砍掉或推出容器。溢出判定用几何断言（容器 `scrollWidth ≤ clientWidth` 或元素不越视口），不用目测截图。
3. **空态截图不算自适应覆盖**：Vite 无后端时全局排查 17 个入口只有空态可验（mock RPC 未接处 404），长字段、多行数据的溢出缺陷验不到（本轮遗留：真实数据态未全量覆盖）。mock 传输层喂的假数据带长字段 / 多行 / 长 locale 文案（ar-SA 截图同此），空态矩阵绿了不写「自适应已验证」。

## 行为测试渲染真组件、断言走 data-testid；表单禁渲染期回落

1. **组件行为测试必须渲染真组件**，用 `data-testid` 取元素断言；禁在测试里重写一份被测逻辑再断言它（测的是测试自己，组件改坏照绿）。
2. **表单控件禁渲染期回落 `value={x || DEFAULT}`**：用户清空后立刻被默认值顶回，永远清不掉。默认值在加载 / 模式切换时一次性预填进 state，渲染只读 state。
3. code-review 派发时这两点都要查：测试是否渲染真组件、表单是否有渲染期回落。

## 同一组件两处调用，功能差距 = props 差异 + 挂载点差异

「A 页已经有 X，让 B 页也支持」类需求，排查从共用组件下手，不从两页各自读代码：

1. 先找共用组件与数据源（例：分组列表 vs 分组详情共用 PlatformRow + usePlatformCards），逐 props 对照——差距常只是某 prop 未传（列表页补 showLastOutcome 即对齐）。
2. 再对照 modal / 浮层的**挂载点**：提前 return 的分支会整段跳过后面的挂载（detailTarget 提前 return 使批量 modal 只在列表分支渲染），搬进共享段即修。
3. 反例：逐页读实现找差异——同一能力读两遍，还把「组件本来就有、只是没传」误判成「页面各自实现」，改动面随之翻倍。

## 「功能没了」类 UI 报告：先真渲染，单测修复不算证据

只靠单测 / 读码的修复在真应用里可能完全无效——真因常在渲染分支没挂载浮层这类结构性位置，定位只能靠隔离内核 + Playwright 真渲染。

1. 报告是「某入口没反应 / 没弹窗」时，第一步查**每个渲染分支**（列表 / 详情 / 提前 return）是否都挂了该浮层，再看 handler。
2. 同一症状第二次修复前，必须跑真渲染复现（取证法见 ui-color-bug-verify.md 规则 2 与 perf-testing.md §1 隔离实例）；复现不出不开第三个改动。
3. 提交说明里写「已在真应用复现并验证」，单测绿只证明单测。
4. 真机症状无代码变动自行消失时，按「成因未定论」关闭：写推测成因与复发时的排查入口（先例：分组拖拽排序 b48d28647 修后一度仍报无效、次日无变动自行恢复，推测拖抓握点落在非激活区，壳层 WKWebView pointermove 排查未出结论），交付口径写「用户已确认正常、成因未定」，不写「已修复」。

## 把一个控件「照搬」到另一处：文案名词与点击区域都要对新位置

1. **i18n key 跨域复用只看文案名词**：zh-Hans 原文里的名词（规则 / 档 / 平台）与新位置的对象一致才复用，否则在新位置同域加专用 key。派发 prompt 写「复用 key」时附原文，不写笼统的「能复用就复用」。
2. **开关 / 按钮嵌进可点击的行、卡片、菜单项**：控件 `onClick={(e) => e.stopPropagation()}`（ModelsMatrixSection.tsx 先例），就近测试断言「点控件后选中项不变」。
3. agent 回报里自列的已知 UI 缺陷（文案错位、点击副作用）属本票范围，同提交修掉，不以「判断不影响使用」留下。

## mock 截图过了、真机三缺陷：失败态截图要模拟真实位置，事件重拉要量次数

mock 截图验收通过 ≠ 真机无缺陷。三类 mock 验不到的实况：① 打开不存在目录的报错其实设置了，但渲染在页顶（`Sessions.tsx:264`）——用户滚到长列表下方点击，提示在视口外，mock 截图在列表顶部触发所以看得到；② osascript `spawn()` 后不等待、脚本里没有 `activate`，Terminal 窗口落在 AiDog 后面，失败被吞（见 test-no-real-calls.md「拉起外部进程」节）；③ 每约 7s 一次 `client-usage-updated` 触发整表重拉加全行重渲染（20s 只读订阅实测 3 次）——300 行时长任务 326ms，加防抖和行 memo 后降到 0。

1. **错误 / 提示类反馈的截图和测试，在触发点远离提示挂载点的位置做**：列表类页面先滚到底部再触发失败态，断言提示元素在视口内（`getBoundingClientRect().top < innerHeight`）。点击操作的反馈一律走视口固定浮层（portal 到 body + `fixed`），或渲染在触发行附近，不放页顶。
2. **mock 截图验证的是渲染，不是失败路径**：mock 制造的报错（如剪贴板 reject）不能代替真实 IPC 的失败分支。拉起外部 app、Finder、终端这类动作，回报单列「真机人工验收」，不写成「已验证失败提示」。
3. **页面订阅后台高频事件做重拉时，验收要量重拉次数**：mock 传输层喂 N≥300 行，连发事件，统计 load 调用次数和 `PerformanceObserver('longtask')`；trailing 防抖、未变行复用旧对象、行组件 `React.memo` 三件按实测决定。

## 小图表票（走势图 / sparkline）：参数一次拍齐，几何验多宽度

几何账派单前就能算：例 49px 宽装 300 秒，约 6 秒落在一个像素上，单秒悬浮值常为 0。每票只改一个参数、用户逐票补口径是返工形态，参数要一次问齐。

1. **派小图表票前，主会话把图的参数列成一张 ask-me 表单一次问完**：时间窗总长与桶宽、桶边界是否对齐绝对时间、线形（竖线 / 折线 / 平滑曲线）、悬浮取值（原始值 / 区间平均）与时间格式（相对 / 时钟）、空值显示。先按实际像素宽算「每像素覆盖多少数据点」写进表单背景，用户才能判断悬浮取值。用户只回单参数指令（如「以 5s 为窗」）时，其余参数照这张表把主会话的解读写进账本（「系解读」），回报列出供下轮复核。
2. **几何类截图与断言至少覆盖 900 / 1024 / 1100 / 1440 四档宽度**：只验一档宽会漏掉窄视口缺陷（例：视口 ≤1100px 时 token 列盖住走势图、真鼠标碰不到悬浮，f8a8c514f 修，几何先红 10 例）。网格行新加一列或改列宽的票，派单写明四档宽度 × zh-Hans / ar-SA 各一组相交断言。
3. **英文 / RTL 截图里出现中文，就当票修或当场开票，不记成「既有遗留」**：例：`formatRelativeTime` 曾硬编码中文，已改走 `Intl.RelativeTimeFormat`（`src/utils/formatters.ts:140`）。
