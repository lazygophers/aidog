# SQLite page cache — 大库二分扫档曲线表（≥4 档）

数据源：`sqlite-cache-sweep.json`（同目录）。库体积 log.db 868~884MB（> 500MB 门槛，采样间因
loadgen 少量写入自然增长，属预期范围）。全程只打 mock 分组，未触碰真实平台。

**采集方式**：每档独立干净重启 `open --env AIDOG_SQLITE_READ_CACHE_KB=<KB> -a AiDog`（default 档
`open -a AiDog` 不设 env），单进程只跑一档，禁同进程混采。default 档取自已落盘的
`baseline-sqlite-cache.md`（n=100）。`-1024`/`-256`/`-64` 三档均以 `sqlite-cache-harness.sh <KB> <label> 100`
各独立重启跑两轮（详见下方「噪声核验」），最终表取复核轮（label 带 `b` 后缀）数据。

**结论：三档三条查询 p95 均未超过基线 +10% 阈值**（最大正向偏移 +6.3%，在 stats_agg 的 -256 档），
memory / heap 5KB 块数则随档位收紧单调下降（真实信号，非噪声）。

p95 仍稳定」同一特征范围内波动）。

## 噪声核验（禁在噪声里硬读趋势）

`-1024`/`-256`/`-64` 三档**首轮**采样（label 无 `b` 后缀，原始文件已随本 subtask 清场删除）曾出现
`platform_balance_agg` p95 异常升高（8.97ms / 8.14ms / 7.27ms，相对基线 +134%~+189%），且不随档位单调
（-1024 反比 -256/-64 更高，无物理解释）。为排除「巧合噪声 vs 真实回归」，对三档各**独立重启复核一轮**
（label 带 `b`），结果全部回落到与基线同量级（3.04/2.64/2.80ms），判定首轮为瞬时噪声（大概率是复核前
连续三次重启后系统/磁盘缓存处于不同热度状态所致），**非缓存收紧导致的真实回归**。曲线表取复核轮数据。
heap 5KB 块数与内存增量两轮高度一致（7471/7473、2995/3014、1899/1902 等，误差 <1%），无此噪声问题，
判定为可信信号。
